# کتابخانه تجهیزات اکسل به‌صورت پیش‌فرض + انتخاب نوع فیوز بر اساس جریان نامی (`T_jar_nami`)

## ۱) چه چیزی تغییر کرد

| مورد | قبل | بعد |
|---|---|---|
| کتابخانه نوع تجهیزات | فقط `dgs_template.json` (نوع‌های قدیمی/نمونه) | **`types_override.xlsx`** — به‌صورت خودکار و پیش‌فرض در GUI (هنگام شروع) و CLI بارگذاری می‌شود |
| نوع فیوز MV | یک نوع ثابت `Default_Fuse_Type` | نوع واقعی بر اساس جریان نامی: `Fuse_Type_1 … Fuse_Type_100` |
| نوع فیوز LV | یک نوع ثابت `LV_Default_Fuse` (۱۰۰ آمپر) | برای هر جریان نامی موجود در داده، یک نوع LV سنتز می‌شود: `LV_Fuse_<A>A` با ولتاژ ۰٫۴ kV |
| کابل زمینی MV | چون نام‌های VDE در کتابخانه نبود، همه به `95-AL-XLPE` می‌افتادند | نام‌های `NA2XSY 1x…/16 (12/20kV)` و `N2XSY 1x…/16 (12/20kV)` در کتابخانه موجود است و مستقیم انتخاب می‌شود |
| ترانس | `{cap}KVA20-O` / `Unknown` | `TRF-Normal-20/0.4 kV-{cap} kVA` و `TRF-AB'-20/0.4 kV-{cap} kVA` (۲۵…۲۵۰۰ kVA) |

## ۲) کتابخانه اکسل

فایل `types_override.xlsx` در ریشه برنامه قرار می‌گیرد و در بسته نصبی هم منتقل می‌شود
(`shp_to_dgs.spec` و `build_tools/build_release.bat`).

| شیت | تعداد ردیف | توضیح |
|---|---|---|
| `TypLne` | ۳۹ | ACSR لخت، هادی روکش‌دار (`MINK-CC`، `HYENA-CC`/`CCT`، `WOLF-CC`/`CCT`)، کابل VDE، `Al_St`، ABC |
| `TypTr2` | ۶۰ | `TRF-Normal-…`، `TRF-AB'-…`، `…KVA20-D`، نسخه‌های قدیمی `-O/-OLS/-H`، `Unknown` |
| `TypLod` | ۱ | `Normal` |
| `TypFuse` | ۲۰ | `Fuse_Type_1 … Fuse_Type_100` (ولتاژ ۲۰ kV) |

نکته‌های ایمپورت:

* ستون‌های `ID` و `fold_id` لازم نیستند؛ خودکار ساخته می‌شوند (ستون‌های چپ‌چین/چیدمان ستون‌ها هم مهم نیست، تطبیق بر اساس نام ستون است).
* سه ردیف تکراری در فایل شما (`ABC33KV120`، `HYENA-CCT`، `WOLF-CCT`) هنگام بارگذاری حذف می‌شوند،
  چون `loc_name` نوع باید یکتا باشد (در لاگ هشدار ثبت می‌شود). اگر دو ردیف هم‌نام **مقادیر متفاوت**
  داشته باشند، ردیف اول نگه داشته و مغایرت گزارش می‌شود.

نحوه استفاده:

* پیش‌فرض: کاری لازم نیست.
* کتابخانه دلخواه: `--types my_types.xlsx` (یا Import در Type Library Editor).
* بازگشت به کتابخانه داخلی: منوی `Settings → Reload Default Type Library (types_override.xlsx)`.
* حذف کامل کتابخانه و استفاده از `dgs_template.json`: `--no-default-types`.

## ۳) انتخاب نوع فیوز با `T_jar_nami`

کلیدهای جدید در `config.json → fuse`:

| کلید | مقدار پیش‌فرض | کارکرد |
|---|---|---|
| `current_field` | `T_jar_nami` | نام فیلد جریان نامی در شیپ‌فایل |
| `type_name_pattern` | `Fuse_Type_{current}` | اولین گزینه: ساخت نام نوع از جریان |
| `match_tolerance_a` | `0` | تلورانس تطبیق دقیق (آمپر) |
| `snap_to_nearest` | `true` | اگر جریان در کتابخانه نبود، نزدیک‌ترین برده شود |
| `snap_prefer` | `lower` | `lower` (کمتر یا مساوی، ایمن‌تر) / `nearest` / `higher` |
| `type_name` | `Fuse_Type_63` | نوع پشتیبان وقتی فیلد خالی یا نامفهوم است |
| `lv_type_name_pattern` | `LV_Fuse_{current}A` | نام نوع LV سنتزشده |
| `lv_type_name` / `lv_irat_a` | `LV_Default_Fuse` / `100` | نوع/جریان LV وقتی داده مقداری ندارد |

ترتیب تصمیم‌گیری:

1. الگوی نام (`63` → `Fuse_Type_63`)؛
2. تطبیق دقیق `irat` در `TypFuse` همان کلاس ولتاژ؛
3. نزدیک‌ترین جریان نامی (پیش‌فرض: کمتر یا مساوی) — **در گزارش مغایرت ثبت می‌شود**؛
4. `fuse.type_name` اگر فیلد خالی/نامفهوم باشد — **در گزارش مغایرت ثبت می‌شود**.

قالب‌های داده‌ای که پشتیبانی می‌شوند: `63`، `63.0`، `"63 A"`، `"فیوز ۶۳"`، و ارقام فارسی/عربی.

مثال: جریان‌های `63`، `55`، `25` و خالی

| مقدار `T_jar_nami` | نوع MV انتخاب‌شده | نوع LV انتخاب‌شده | گزارش مغایرت |
|---|---|---|---|
| `63` | `Fuse_Type_63` | `LV_Fuse_63A` | — |
| `55` | `Fuse_Type_50` | `LV_Fuse_55A` | `fuse_rating_snapped` |
| `25` | `Fuse_Type_25` | `LV_Fuse_25A` | — |
| خالی | `Fuse_Type_63` (پشتیبان) | `LV_Default_Fuse` | `fuse_current_missing` |

## ۴) تغییرات پیکربندی مرتبط با کتابخانه جدید

چون نام‌های قدیمی در کتابخانه جدید وجود ندارند، این کلیدها به‌روزرسانی شدند
(وگرنه بی‌سروصدا به fallback می‌افتادند):

```json
"line_type": {
  "cable_default": "NA2XSY 1x95/16 (12/20kV)",
  "mln_default":   "N2XSY 1x95/16 (12/20kV)",
  "uml_default":   "NA2XSY 1x95/16 (12/20kV)",
  "covered_by_section": {"35": "35-Covered", "70": "MINK-CC", "126": "HYENA-CC", "185": "WOLF-CC"}
}
```

موارد باقی‌مانده که باید بدانید:

* هادی روکش‌دار با مقطع ۲۲۵/۲۲۶ (LYNX) در کتابخانه نوع `-CC` ندارد → به `covered_default`
  (`35-Covered`) می‌افتد و در گزارش مغایرت می‌آید. اگر داده دارید، ردیف `LYNX-CC` را به اکسل اضافه کنید.
* کابل آلومینیوم ۵۰۰ mm² نام VDE ندارد (فقط نسخه مسی) → به `uml_default` می‌افتد (گزارش می‌شود).
* ظرفیت بانک خازنی همچنان ثابت است (`0.15 Mvar`)؛ مبدأ داده‌ای ندارد.
* وضعیت فیوز (`T__outserv`) مثل قبل خوانده نمی‌شود و `on_off = 1` است.
* `T_strn` = ظرفیت ترانس؛ کلاس تلفات پیش‌فرض «کم‌تلفات» (`AB'`) و عایق پیش‌فرض `O` است.

## ۵) ساخت نسخه اجرایی

منطق فیوز داخل `shp2dgs/core/converter.py` است که در بیلد نهایی به `converter.*.pyd`
کامپایل می‌شود؛ پس پس از این تغییر:

```bat
BUILD.bat            REM یا build_tools\build_core.py سپس build_release.bat
```

و مطمئن شوید `types_override.xlsx` کنار `GeoGrid.exe` قرار دارد (اسکریپت بیلد اکنون
وجود آن را بررسی و در صورت نبود، بیلد را متوقف می‌کند).
